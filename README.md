# 문제

> **학생이 다양한 유형의 문제를 풀고 제출할 수 있는 웹 기반 문제 풀이 플랫폼**

---

## 1. 프로젝트 소개

### 1.1 프로젝트 목적

학생들이 수업에서 배운 내용을 문제를 통해 확인하고,
어떤 내용을 잘 이해하고 있으며 어떤 부분을 어려워하는지 파악하기 위한 웹앱이다.

교사는 학생들의 문제 풀이 결과를 통해 학생별·문제별·단원별 이해도를 확인할 수 있다.

### 1.2 주요 사용자

* 학생
* 교사

### 1.3 활용 영역

* 수업
* 형성평가
* 수행평가
* 복습
* 자기주도 학습
* 시험 대비

### 1.4 결과물 형태

* 웹 애플리케이션

### 1.5 현재 개발 상태

* 2단계 — 객관식 문제 완료

---

## 2. 해결하려는 문제

### 2.1 학생 측면

학생은 자신이 어떤 내용을 잘 이해하고 있으며, 어떤 내용을 어려워하고 있는지 스스로 파악하기 어렵다.

문제를 푼 이후에도 단순히 점수만 확인하는 경우가 많아, 자신의 취약 개념을 체계적으로 파악하기 어렵다.

### 2.2 교사 측면

교사는 학생들이 제출한 결과를 하나씩 확인해야 하기 때문에 다음 내용을 빠르게 파악하기 어렵다.

* 학생별 이해도
* 문제별 정답률
* 자주 틀리는 개념
* 학생들이 공통적으로 어려워하는 부분
* 단원별 학습 성취도
* 학생별 취약 영역

### 2.3 기존 문제 풀이 방식의 한계

문제 유형에 따라 서로 다른 인터페이스를 사용하거나 별도의 서비스를 이용해야 하는 경우가 있다.

예:

* 객관식
* 단답형
* 빈칸 채우기
* SQL 작성
* 프로그래밍 코드 작성

이를 하나의 웹앱에서 통합적으로 제공하고자 한다.

---

## 3. 해결 방법

### 3.1 문제 인터페이스 통합

다양한 문제를 일정한 디자인과 인터페이스로 변환하여 학생에게 제공한다.

문제 유형은 서로 다르지만 전체적인 문제 풀이 흐름은 통일한다.

```text
문제 확인
↓
답안 작성
↓
제출
↓
채점
↓
결과 확인
```

### 3.2 다양한 문제 유형 지원

다음과 같은 문제 유형을 지원한다.

* 객관식
* 복수 선택
* OX 문제
* 단답형
* 빈칸 채우기
* 서술형
* SQL 작성
* 코드 작성

구체적인 문제 예시는 문서 하단의 부록을 참고한다.

### 3.3 풀이 결과 저장

학생의 문제 풀이 결과를 저장한다.

예:

* 학생이 작성한 답안
* 정답 여부
* 획득 점수
* 제출 시간
* 문제 풀이 횟수
* 문제별 점수
* 문제 세트별 점수

### 3.4 학습 분석

저장된 데이터를 이용하여 학생과 교사가 학습 상태를 파악할 수 있도록 한다.

예:

* 학생별 정답률
* 문제별 정답률
* 단원별 정답률
* 자주 틀리는 문제
* 취약 개념
* 반복해서 틀리는 문제
* 학생별 학습 변화

## 4. 핵심 기능

## 4.1 학생 기능

### 문제 목록 확인

학생이 자신에게 배정된 문제 또는 문제 세트를 확인한다.

### 문제 풀이

문제 유형에 맞는 인터페이스를 제공한다.

예:

* 객관식 → 선택 버튼
* 단답형 → 텍스트 입력
* SQL → SQL 입력 영역
* 코드 작성 → 코드 에디터

### 답안 제출

학생이 작성한 답을 서버로 제출한다.

### 결과 확인

설정에 따라 다음 정보를 확인할 수 있다.

* 정답 여부
* 점수
* 정답
* 해설
* 자신의 답안

### 학습 기록 확인

학생 자신의 학습 결과를 확인한다.

예:

* 전체 정답률
* 단원별 정답률
* 틀린 문제
* 취약 영역
* 최근 문제 풀이 기록
* 재응시 기록

---

## 4.2 교사 기능

### 문제 생성

교사가 문제를 등록한다.

### 문제 수정 및 삭제

등록한 문제를 수정하거나 삭제한다.

### 문제 세트 생성

여러 문제를 하나의 문제 세트로 구성한다.

예:

* SQL 1차시 확인 문제
* 중간고사 대비 문제
* React 기초 문제
* Node.js 모듈 문제

### 학생에게 문제 배정

학생 또는 학급에 특정 문제 세트를 배정한다.

### 제출 결과 확인

학생들의 제출 결과를 확인한다.

### 결과 분석

다음과 같은 데이터를 확인한다.

* 학생별 점수
* 문제별 정답률
* 가장 많이 틀린 문제
* 단원별 이해도
* 학생별 취약 영역

---

## 4.3 기본 요구사항

### 문제 풀이

* 학생은 문제 세트에 포함된 문제를 확인할 수 있어야 한다.
* 학생은 문제 유형에 맞는 답안을 작성할 수 있어야 한다.
* 학생은 답안을 제출할 수 있어야 한다.
* 제출 결과는 서버에 저장되어야 한다.

### 문제 관리

* 교사는 문제를 생성할 수 있어야 한다.
* 교사는 문제를 수정할 수 있어야 한다.
* 교사는 문제를 삭제할 수 있어야 한다.
* 교사는 문제를 문제 세트에 포함할 수 있어야 한다.
* 문제의 순서를 변경할 수 있어야 한다.

### 결과 관리

* 학생의 답안을 저장해야 한다.
* 문제별 채점 결과를 저장해야 한다.
* 문제 세트 전체 점수를 계산할 수 있어야 한다.
* 학생의 응시 기록을 확인할 수 있어야 한다.

# 5. 문제 시스템

## 5.1 문제의 기본 구조

모든 문제는 공통적으로 다음 정보를 가진다.

* 문제 ID
* 제목
* 문제 내용
* 문제 유형
* 정답
* 배점
* 해설
* 단원
* 난이도
* 생성일
* 수정일
* 생성자

예:

```json
{
  "id": "q001",
  "type": "multiple-choice",
  "title": "트랜잭션 기초",
  "content": "다음 중 트랜잭션을 확정하는 명령어는?",
  "choices": [
    "COMMIT",
    "ROLLBACK",
    "SELECT",
    "DELETE"
  ],
  "answer": 0,
  "score": 5,
  "difficulty": "easy",
  "tags": [
    "database",
    "transaction"
  ]
}
```

---

## 5.2 문제 유형

### 객관식

하나의 정답을 선택한다.

### 복수 선택

여러 개의 정답을 선택한다.

### OX

참 또는 거짓을 선택한다.

### 단답형

짧은 텍스트 답안을 작성한다.

### 빈칸 채우기

문장 또는 코드의 특정 부분을 입력한다.

### 서술형

학생이 문장 형태로 답안을 작성한다.

### SQL 작성

SQL 코드를 직접 작성한다.

향후 다음 기능도 고려한다.

* SQL 자동 실행
* 실행 결과 확인
* 결과 테이블 비교
* SQL 문법 오류 확인
* 테스트 데이터 기반 자동 채점

### 코드 작성

JavaScript 등 프로그래밍 코드를 작성한다.

향후 다음 기능을 고려한다.

* 코드 실행
* 테스트 케이스 실행
* 실행 결과 비교
* 자동 채점

---

## 5.3 공통 지문

여러 문제가 하나의 코드, 글, 표, 이미지 또는 데이터베이스 구조를 공통으로 사용하는 경우가 있다.

예:

* 하나의 JavaScript 코드를 보고 16~23번 문제 풀이
* 하나의 데이터베이스 테이블 구조를 보고 여러 SQL 문제 풀이
* 하나의 글을 읽고 여러 객관식 문제 풀이

공통 지문은 개별 문제와 분리하여 관리한다.

### 공통 지문 유형

* 일반 텍스트
* 코드
* 표
* 데이터베이스 테이블 구조
* 이미지
* 복합 자료

예:

```json
{
  "id": "context001",
  "type": "code",
  "language": "javascript",
  "content": "const USER_PROFILES = {...}"
}
```

문제에서는 공통 지문의 ID만 연결한다.

```json
{
  "id": "q016",
  "contextId": "context001",
  "type": "multiple-choice",
  "content": "USER_PROFILES의 데이터 구조에 대한 설명으로 옳은 것은?"
}
```

## 5.4 문제 세트

여러 개의 문제를 묶어 하나의 학습 또는 평가 단위로 구성한다.

예:

* JavaScript 객체와 배열
* SQL SELECT 기초
* 트랜잭션 형성평가
* 중간고사 대비 문제

문제 세트는 다음 정보를 가진다.

* 문제 세트 ID
* 제목
* 설명
* 포함된 문제
* 문제 순서
* 총점
* 공개 여부
* 시작일
* 마감일
* 생성자

예:

```json
{
  "id": "set001",
  "title": "SQL SELECT 기초",
  "description": "SELECT와 WHERE 기초 확인 문제",
  "questions": [
    "q001",
    "q002",
    "q003"
  ]
}
```

## 5.5 답안

학생이 하나의 문제에 입력한 응답이다.

문제 유형에 따라 답안의 형태가 다르다.

예:

* 객관식 → 선택한 번호
* 복수 선택 → 선택한 번호 목록
* OX → true / false
* 단답형 → 입력한 문자열
* SQL → 작성한 SQL 코드
* 서술형 → 작성한 문장

예:

```json
{
  "questionId": "q001",
  "answer": 2
}
```

SQL 문제의 예:

```json
{
  "questionId": "q010",
  "answer": "SELECT title, price FROM books WHERE price >= 15000;"
}
```

## 5.7 응시 기록

하나의 문제 세트를 여러 번 응시할 수 있도록 각 시도를 별도로 기록한다.

예:

```text
홍길동

SQL SELECT 기초

1차 시도 → 70점
2차 시도 → 90점
3차 시도 → 100점
```

각 응시는 다음 정보를 가진다.

* 응시 번호
* 시작 시간
* 제출 시간
* 획득 점수
* 제출 답안
* 완료 여부

## 5.8 채점 방식

문제 유형에 따라 다른 채점 방식을 사용한다.

### 객관식

정답 번호와 학생이 선택한 번호를 비교한다.

### 복수 선택

정답 목록과 학생 선택 목록을 비교한다.

### OX

정답의 참·거짓 값과 비교한다.

### 단답형

다음 방법을 고려한다.

* 완전 일치
* 앞뒤 공백 제거 후 비교
* 전체 공백 제거 후 비교
* 대소문자 무시
* 여러 개의 정답 허용

예:

```text
서울
서울특별시
서울 특별시
```

를 모두 정답으로 인정할지 설정할 수 있도록 고려한다.

### 서술형

기본적으로 교사가 직접 채점한다.

향후 AI를 이용한 채점 보조 기능을 고려할 수 있다.

### SQL

향후 다음 방식을 고려한다.

* SQL 실행 성공 여부
* 결과 컬럼 비교
* 결과 행 비교
* 결과값 비교
* 결과 순서 비교
* 특정 SQL 문법 사용 여부 확인

예:

```text
학생 A

SELECT title, price
FROM books
WHERE price >= 15000;
```

```text
학생 B

SELECT title, price
FROM books
WHERE 15000 <= price;
```

두 SQL의 작성 방법은 다르지만 결과가 같다면 정답으로 처리할 수 있도록 하는 방식을 고려한다.

# 6. 문제 화면 디자인

## 6.1 기본 원칙

문제 유형이 달라도 전체적인 화면 구조는 동일하게 유지한다.

```text
문제 번호
↓
공통 지문 또는 참고 자료
↓
문제 내용
↓
문제별 입력 영역
↓
답안 저장
↓
다음 문제
```

문제 세트의 마지막 문제에서는 다음과 같은 흐름을 제공한다.

```text
마지막 문제
↓
답안 확인
↓
최종 제출
```

### 문제 2

도서 테이블에서 분류가 `'소설'`, `'과학'`, `'역사'` 중 하나인 책을 조회하시오.

단, `IN`을 사용한다.

결과로 나와야 하는 속성:

* 도서번호
* 제목
* 분류
* 가격

예상 답안:

```sql
SELECT 도서번호, 제목, 분류, 가격
FROM 도서
WHERE 분류 IN ('소설', '과학', '역사');
```

# 부록 C. 초기 데이터 관계 개념

현재 시스템의 핵심 데이터 관계는 다음과 같다.

```text
User
 │
 │ 풀이
 ↓
Submission
 │
 ├── Answer
 ├── Answer
 └── Answer
       │
       ↓
    Question

Question
 │
 └── Context

QuestionSet
 │
 ├── Question
 ├── Question
 └── Question
```

조금 더 단순하게 표현하면 다음과 같다.

```text
사용자
  ↓
문제 세트
  ↓
문제
  ↓
답안
  ↓
채점
  ↓
제출 기록
  ↓
학습 분석
```
